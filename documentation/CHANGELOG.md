# Changelog of aha-aql.spec.md

- 2026-11-25: Version 0.20.1. The rule that a row has each label once is now in parse-statement, directly before the rule for the message S15. Since version 0.18.0 it was the first line of the file, above the title, where an editing mistake of that unit had put it. Its text is unchanged.
- 2026-11-24: Version 0.20.0. FakeAha is now an HTTPS server and proxy outside the server process, reached through HTTPS_PROXY and SSL_CERT_FILE, and the server has no hook for tests. Six examples say what a test sees from outside, the example for a direct connection is removed, and the certificate check has an example. The annotations of `query` are complete, the four warnings have fixed texts (G13 to G16), META names the module, and the rule on environment variables is one that a server can meet. DEPLOYMENT says that the container image listens on a loopback address and which trust store it has. The review of the first implementation found these points on 2026-11-24 (F-013, F-022, F-023, F-024, F-026 and F-028), and the maintainer chose the form of the tests and the listen address of the image.
- 2026-11-24: Version 0.19.0. The server keeps nothing that it read from Aha! between statements: the product list, the custom field definitions, the options and the workflows are read at most once per statement. Earlier versions said that a list may be kept in stdio mode, which allowed two servers with different request counts, and the examples count requests. An IN list is now checked completely before the first request, and `description` of products is requested only when a statement uses it. The maintainer chose the first rule on 2026-11-24 for finding F-012 of the review; the other two are F-020 and F-025, a new INVARIANT states the first rule, and three examples are new.
- 2026-11-24: Version 0.18.2. The example entity_without_custom_fields now lists the field success_metric of goals after name, as the catalog has it since version 0.11.0. The text of the example was not changed with that version, which was an omission. The review of the first implementation found it on 2026-11-24 (F-016); the implementation and its test already follow the catalog.
- 2026-11-24: Version 0.18.1. A kind that starts with a vowel gets the article `an` in messages, and a message for the entity me says `user`. The note H03 names the id field of the entity, which is `key` for products, and S05 writes the id in capital letters. W25 for a requirement now shows a statement that lists requirements by their feature, because the server refuses the statement with `product` that the message had before. The review of the first implementation found these texts on 2026-11-24 (F-011 and F-015); one example is new.
- 2026-11-24: Version 0.18.0. A statement can no longer produce a JSON object that has the same member twice. A write statement that sets one field twice is refused with the new message W33, and the result of an UPDATE shows `name` once. A read statement leaves out a select item that repeats an earlier one, and it refuses two different items with one label (new messages S15 and S16). The review of the first implementation found request bodies and results with repeated members on 2026-11-24 (F-007 and F-008); a new INVARIANT states the rule, and three examples are new.
- 2026-11-24: Version 0.17.0. `=`, `!=` and IN on a field with several values now look for the value among the values of the field: `tags = 'urgent'` is true for a feature with the tags urgent and customer. Earlier versions compared the joined text. A value with commas means that the field has each of its parts, and CONTAINS stays a search in the text. The maintainer chose this rule on 2026-11-24 for finding F-005 of the review; one example is new, and the fixture account has tags on two features.
- 2026-11-24: Version 0.16.0. A value in a condition now has to fit the type of its field (new messages V01 and V02), and a timestamp is compared as a point in time. Earlier versions compared dates and timestamps as text and gave wrong results without an error. NULL and empty text in an IN list stand for a field without a value, and `field = ''` is read as IS NULL, also in a guard of a write statement. The review of the first implementation found these points on 2026-11-24 (F-003, F-004 and F-009), and the maintainer chose the meaning of NULL in a list; four examples are new.
- 2026-11-24: Version 0.15.0. Text with numbers is now ordered by the numbers, so DEMO-9 comes before DEMO-10 in ORDER BY, MIN, MAX and comparisons. The grammar of a read statement says what a label is, where `*` can stand and what a key of ORDER BY is, and records without a value in a group field are one group. The review of the first implementation found these points on 2026-11-24 (F-002, F-017, F-018 and F-019); touched are build-rows, evaluate-condition, parse-statement and error-messages, and five examples are new.
- 2026-11-24: Version 0.14.0. A note for an empty result no longer says that a record does not exist when it exists: H03 is given only when the id route found no record. The new note H08 says that the record exists and that another condition is not true for it, and the new note H09 lists the entities that a product has statuses for. The review of the first implementation found both points on 2026-11-24 (F-001 and F-021); touched are read-statement and error-messages, and two examples are new.
- 2026-11-24: Version 0.13.0. The field success_metric of goals can be set in INSERT only. A run of aha-checks.sh on 2026-11-24 sent an update with success_metric.name. Aha! answered without an error and left the text as it was. An UPDATE that assigns the field is now refused with W16, before any request. The catalog column Writable has the new value INSERT only, and DESCRIBE shows it. The same run confirmed that a new goal takes its status inside success_metric.
- 2026-11-24: Version 0.12.1. The PRECONDITIONS section now says what the runs of aha-checks.sh on 2026-11-24 observed on one account, and what is still not observed. Two statements are new: the values of an update of a feature, and the create and delete routes of the catalog. No rule of the specification changes.
- 2026-11-24: Version 0.12.0. The statuses of a record kind now come from the workflow that the record of the product names for that kind. The member has a name such as epic_workflow. Earlier versions looked for a workflow with the record type of the entity. The run of aha-checks.sh on 2026-11-24 showed that features, epics and requirements share one workflow with the record type Feature. Every status of an epic or a requirement would therefore be refused with W21. The entity statuses now needs two requests and delivers the statuses of a shared workflow once per entity.
- 2026-11-24: Version 0.11.0. Goals have the new field success_metric, and INSERT INTO goals requires it (message W19). The run of aha-checks.sh on 2026-11-24 showed that Aha! creates no goal without a success metric that has a name. write-request sends the metric as an object with the member name. The status of a new goal goes into that object, and an update sends workflow_status as before. The second source of the status of a goal is removed, because a goal has no member workflow_status.
- 2026-11-24: Version 0.10.0. The entity epics now follows the API record of an epic. The field release comes from release.reference_num, and the field color is removed. The run of aha-checks.sh on 2026-11-24 read 200 epics of one account: none had release_reference_num or color, and all had release.reference_num.
- 2026-11-24: Version 0.9.0. INTERFACES now gives the JSON form of the answers of Aha!. It names the member that has a record or a list, the page information in the member pagination, and the answers for workflows and options. A long text is an object with the member body, and the parameter fields has top-level names only. An answer in another form is the failure Rejected with the text "the answer has an unknown form", and FakeAha answers in these forms. Earlier versions left the forms to the translator; they come from the API documentation and from the prototype of 2026-11-12. Touched: aha-request, convert-record, the MECHANISM of plan-fetch, one new precondition and one example; two examples are new.
- 2026-11-24: Version 0.8.0. SELECT * for one record that the statement selects by its id field now also shows the custom fields that have a value in that record. They come after the catalog fields, in the order of their names. The maintainer chose this on 2026-11-24 in place of decision 21 of version 0.4.0, and asked for it on products too. For a product the server reads the product once more with GET /products/{product}, because the product list has no custom fields. A list shows catalog fields only, as before. Touched: read-statement, build-rows, the note text of describe-statement, the catalog entry of products, FakeAha, three invariants and five examples; one example is replaced and two are new.
- 2026-11-24: Version 0.7.0. The DEPLOYMENT section now has the declarations that the deployment template mcp-server 0.3.24 asks for. They are the command words query and execute, the environment variables of load-configuration, and every AqlError of the two tools as a tool execution error. The table of deviations from template 0.3.23 is gone, because the template has rows for these three points since 0.3.24. No behavior, type, interface, invariant or example changed.
- 2026-11-24: Version 0.6.0. The TYPES section can now be sliced. pcd-slice 0.1.1 reported 11 undefined types for version 0.5.0, because it counts only "Name :=" lines in the fenced block as definitions. The enumerations ErrorKind, FieldType, CustomKind and RecordKind are therefore prose definitions, with the values and descriptions of the former tables. The variants of Condition and of ApiFailure have definitions of their own. Unreachable names its cause, which selects the reason text of message X02. No behavior, interface, invariant or example changed.
- 2026-11-24: Version 0.5.0. Six MILESTONE sections are new. They are the scaffold milestone 0.0.0 and the milestones 0.1.0 to 0.5.0, with three to seven behaviors each, in the order of their dependencies. The specification has 26 behaviors, and with milestones each translation pass has a small part of them. No behavior, type, interface, invariant or example changed.
- 2026-11-24: Version 0.4.0. The new behavior custom-fields reads the custom field definitions of the account. A statement can now read a custom field as custom.<key> in SELECT, WHERE, GROUP BY and ORDER BY, and UPDATE can set it. The maintainer asked for reading and writing on 2026-11-24. Touched as a consequence: the types FieldName, EntityDef and MaxListed, the new types CustomField, CustomKind and TextList, the list rule of AhaAPI and the fixture of FakeAha; the behaviors query, tool-registration, read-statement, describe-statement, insert-statement, update-statement, delete-statement, parse-statement, entity-catalog, resolve-names, plan-fetch, convert-record, evaluate-condition, check-write-values, write-request and error-messages (N02, W16 and W17 changed; N04 to N07, W31, W32 and X05 new); three PRECONDITIONS and four INVARIANTS are new, and three INVARIANTS have a new text.
- 2026-11-24: Version 0.3.1. Three small changes follow the review of the open questions. The author line has a new address, the User-Agent has the address of the project, and load-configuration answers an unknown first word with the new message G12.
- 2026-11-13: Version 0.3.0. The environment is now a regular source of settings: a new invariant lists every variable that the server reads, and an option takes precedence. load-configuration also reads AHA_DEFAULT_PRODUCT and AHA_READ_ONLY and ignores AHA_API_KEY in http mode; aha-request uses the proxy and the trust store of the environment. The reason is the use in a sandbox that gives credentials through the environment and sends all traffic through a proxy.
- 2026-11-13: Version 0.2.0. The specification now describes a new MCP server, mcp-server-aha-aql, on the template mcp-server, and no longer an amendment of aha-studio. New are manual mode, configuration from options and two environment variables, an account per request in http mode, and own HTTPS requests to Aha!. The operator profile, writes by predicate, custom field references, writes on products and DELTA are removed; the file was aha-studio-aql.spec.md until 0.1.0.
- 2026-11-13: Version 0.1.0. First version: the amended AQL of aha-studio on the base version 0.12.0. It has the two MCP tools query and execute, the entity catalog, a read path that evaluates every condition on complete records, and write statements that change one record found by its id. It follows the analysis of 2026-11-11 and the test results of 2026-11-12, and it is the input for patches to the upstream project.
